# LinuxBenchHub Benchmark Technical Specification

This document details the benchmark suites, automated capture workflows, hardware environments, and static export architecture of LinuxBenchHub.

## 1. Phoronix Test Suite (PTS) Workloads

Captured monthly across identical virtual hardware:

- **`pts/c-ray-2.0.0`**: CPU raytracing performance (1080p @ 16 rays per pixel). Output unit: `Seconds` (lower is faster).
- **`pts/tinymembench-1.0.2`**: Sub-cache memory bandwidth (`memcpy` and `memset`). Output unit: `MB/s` (higher is faster).
- **`pts/aircrack-ng-1.3.0`**: Multithreaded cryptographic network hash rate. Output unit: `k/s` (higher is faster).
- **`pts/fio-2.1.0`**: Flexible I/O Tester for synchronous and asynchronous disk I/O throughput and latency (sequential and random read/write). Output unit: `MB/s` / `IOPS` (higher is faster).

## 2. Infrastructure & Execution Pipelines

### x86_64 Containerized Capture

- Matrix workflow (`.github/workflows/capture-benchmarks.yml`) executing on GitHub-hosted `ubuntu-latest` runners.
- Runs distro container instances: `ubuntu:26.04`, `fedora:44`, `debian:13`.

### arm64 Native VM Capture

- Always-Free Oracle Cloud Infrastructure Ampere A1 VM (4 OCPU, 24 GB RAM, Neoverse-N1).
- Infrastructure provisioned via OpenTofu in `infra/oci-ampere/`.
- CI SSH orchestration triggers `/usr/local/bin/lbh-capture` non-interactively, returning `composite-latest.xml`.

## 3. Web Showcase & Static Export Engine

- **Rails 8 App (`website/`)**: Built without Active Record (`--skip-active-record`). Parses markdown writeups generated by `benchmarks/generate_writeup.rb`.
- **Static Export**: Executed via `rake export:static`, rendering pre-baked static HTML pages and compiled assets into `website/export/` for Vercel deployment.
- **Cross-Distro Comparison**: Route `/compare` renders side-by-side performance matrices across distros.

## 4. Automated Workload Dispatch Engine

The automated workload dispatch system (`bin/lbh-dispatch` and `lib/linux_bench_hub/workload_dispatch/`) orchestrates reproducible benchmark execution pipelines across CPU, memory bandwidth, and disk I/O.

- **Reproducibility**: Deterministic batch mode configuration, unprompted interactive response streams, and isolation flags eliminate interactive drift.
- **Multi-Target Execution**: Supports native local execution (`LocalTarget`), containerized runs (`DockerTarget`), remote cloud execution (`SshTarget`), and validation runs (`SimulatedTarget`).
- **Telemetry & Manifests**: Every run records an atomic `manifest.json` capturing execution duration, kernel details, target environment, per-workload metrics (mean and standard deviation), and generated `composite.xml` artifacts.
- **Specification**: See [`docs/specs/workload_dispatch.md`](specs/workload_dispatch.md) for full technical details.
